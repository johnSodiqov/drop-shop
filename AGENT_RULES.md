# AGENT RULES — DROPSTORE

## 1. Общие правила

- ТЗ в корне проекта является главным источником требований.
- Не изменяй требования без обоснования.
- Не удаляй существующий функционал без необходимости.
- Не переписывай весь проект ради небольшого улучшения.
- Не создавай ненужные файлы.
- Не устанавливай дополнительные библиотеки без обоснования.
- Не создавай архитектурные решения, которые усложняют MVP.

## 2. Ограничения архитектуры

- Соблюдай Separation of Concerns.
- Используй SOLID там, где это оправдано.
- Избегай чрезмерной абстракции.
- Не допускай дублирования бизнес-логики.
- Не используй глобальные переменные для бизнес-данных.
- Не смешивай frontend и backend.
- Не размещай SQL-запросы непосредственно в HTML.
- Не помещай всю бизнес-логику в один файл.
- Не создавай монолитные контроллеры.

## 3. Backend

- Используй NestJS и TypeScript.
- Работай с PostgreSQL через Prisma ORM; изменения схемы выполняй миграциями Prisma.
- Контроллеры должны делегировать бизнес-логику сервисам.
- Используй DTO, class-validator и class-transformer для проверки входных данных.
- Все входные данные должны валидироваться.
- Все бизнес-операции должны выполняться на backend.
- Все защищённые endpoints должны проверять авторизацию.
- Все административные endpoints должны проверять роль ADMIN.
- Все агентские endpoints должны проверять роль AGENT.
- Пользователь не должен получать доступ к данным других пользователей.

## 4. Database

- Используй PostgreSQL и Prisma ORM.
- Не храни пароли в открытом виде.
- Используй foreign keys.
- Используй индексы для часто используемых запросов.
- Не допускай дублирования SKU.
- Не допускай отрицательных остатков.
- Изменения базы данных выполняй через Prisma Migrate.
- Используй транзакции для заказов и складских операций.
- Денежные значения храни в DECIMAL, а не FLOAT.
- Время храни в UTC с явным типом PostgreSQL `Timestamptz`.
- Учитывай валюту UZS.

## 5. Frontend

- Используй единый дизайн-системный подход.
- Не дублируй CSS.
- Не используй inline styles без необходимости.
- Не создавай чрезмерно сложные компоненты.
- Не используй тяжелые библиотеки для простых задач.
- Интерфейс должен быть адаптивным.
- Все формы должны иметь валидацию.
- Все кнопки должны выполнять реальные действия.
- Не создавай декоративные кнопки без функциональности.
- Обязательно реализуй loading, error и empty states.

## 6. Безопасность

Запрещено:
- Хранить секреты в frontend.
- Хранить пароли в открытом виде.
- Использовать SQL-запросы с конкатенацией пользовательского ввода.
- Отключать проверки авторизации ради удобства.
- Доверять цене, переданной клиентом.
- Доверять роли, переданной клиентом.
- Разрешать агенту менять закупочную цену.
- Разрешать пользователю менять чужие заказы.
- Оставлять тестовые административные пароли в production.

Обязательно:
- CSRF protection.
- XSS protection.
- Защита запросов через параметризованные операции Prisma.
- Server-side validation.
- Rate limiting.
- Безопасная JWT-аутентификация и HttpOnly refresh-cookie.
- Password hashing.
- Проверка прав доступа.
- Защита от повторных заказов.

## 7. Склад и заказы

- Проверяй остатки на сервере.
- Используй транзакции.
- Не допускай двойного списания.
- Не допускай отрицательных остатков.
- Используй атомарные операции.
- Фиксируй изменения остатков.
- Сохраняй цену товара на момент заказа.
- Сохраняй закупочную стоимость на момент заказа.
- Не пересчитывай исторические заказы по текущей цене товара.
- При отмене заказа возвращай остатки только один раз.

## 8. Telegram

- Telegram Token хранится только в .env.
- Не публикуй токены.
- Не отправляй уведомления до фиксации заказа в базе.
- Ошибка Telegram не должна отменять заказ.
- Реализуй логирование ошибок.
- Используй retry-механизм для уведомлений.

## 9. Качество кода

- Код должен быть читаемым.
- Используй понятные названия.
- Избегай magic numbers.
- Избегай чрезмерно длинных функций.
- Не оставляй мёртвый код.
- Не оставляй TODO без причины.
- Не подавляй ошибки без обработки.
- Не используй @ для скрытия ошибок PHP.
- Не игнорируй предупреждения.

## 10. Тестирование

- Тестируй критические бизнес-процессы.
- Тестируй все роли.
- Тестируй ограничения доступа.
- Тестируй складские операции.
- Тестируй отмену заказов.
- Тестируй расчёт прибыли.
- Тестируй Telegram-интеграцию.
- Не считай ручной просмотр интерфейса полноценным тестированием backend.

## 11. Работа нескольких агентов

Если проект разрабатывается несколькими агентами:

- Не изменяй файлы, принадлежащие другому агенту, без согласования.
- Используй единые API-контракты.
- Используй единые naming conventions.
- Не создавай альтернативные схемы базы данных.
- Не создавай дублирующие сервисы.
- Не изменяй общую архитектуру без согласования с Technical Lead.
- Перед интеграцией проверяй совместимость модулей.
- Каждый агент должен документировать изменения.

## 12. Git

- Не удаляй историю Git.
- Не выполняй destructive Git-команды без разрешения.
- Не перезаписывай чужие изменения.
- Используй осмысленные commit messages.
- Не коммить .env.
- Не коммить секреты.
- Не коммить временные файлы и логи.

## 13. Финальная проверка

Перед завершением:

- Проверь сборки TypeScript Backend и Frontend.
- Проверь структуру базы данных.
- Проверь API.
- Проверь авторизацию.
- Проверь роли.
- Проверь создание заказа.
- Проверь склад.
- Проверь Telegram.
- Проверь адаптивность.
- Проверь ошибки консоли браузера.
- Проверь отсутствие секретов в репозитории.

Не объявляй проект завершённым, если критические функции не работают.
