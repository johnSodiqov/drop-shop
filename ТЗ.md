# Техническое задание
## DropStore — Dropshipping-платформа

### 1. Общая концепция

Разработать минималистичную веб-платформу для организации дропшиппинга.

Владелец платформы (администратор) размещает товары на сайте, управляет складскими остатками и ценами.

Агенты регистрируются на платформе, выбирают товары, рекламируют их потенциальным покупателям и оформляют заказы через сайт.

Администратор получает заказы, обрабатывает их и самостоятельно организует поставку товаров.

Платформа должна быть простой, быстрой, адаптивной и удобной для использования с мобильных устройств.

### 2. Роли пользователей

В системе должно быть три основные роли.

#### 2.1. Администратор

Администратор имеет полный доступ к системе.

Возможности:
- Просмотр общей статистики.
- Добавление товаров.
- Редактирование товаров.
- Удаление товаров.
- Управление ценами.
- Управление складскими остатками.
- Управление категориями.
- Просмотр всех заказов.
- Изменение статусов заказов.
- Просмотр списка зарегистрированных пользователей.
- Изменение ролей пользователей.
- Блокировка и разблокировка аккаунтов.
- Просмотр продаж каждого агента.
- Получение уведомлений о новых заказах в Telegram.
- Управление настройками платформы.

#### 2.2. Агент

Агент — это зарегистрированный пользователь, который рекламирует товары и привлекает покупателей.

Возможности:
- Регистрация по номеру телефона.
- Авторизация.
- Просмотр каталога товаров.
- Просмотр фотографий и описаний товаров.
- Просмотр закупочной цены.
- Установка собственной наценки в рамках разрешённых правил.
- Просмотр итоговой цены для покупателя.
- Создание заказа.
- Добавление данных покупателя.
- Просмотр собственных заказов.
- Просмотр статусов заказов.
- Просмотр истории продаж.
- Просмотр своей прибыли.
- Получение персональной ссылки на товар.
- Копирование ссылки для распространения.
- Просмотр статистики продаж.

Агент не должен иметь возможности редактировать складские остатки или закупочные цены.

#### 2.3. Пользователь (покупатель)

Покупатель может:
- Зарегистрироваться по номеру телефона.
- Авторизоваться.
- Просматривать каталог товаров.
- Просматривать карточки товаров.
- Добавлять товары в корзину.
- Оформлять заказ.
- Указывать имя, номер телефона и адрес доставки.
- Просматривать историю своих заказов.
- Отслеживать статус заказа.

Покупатель не имеет доступа к закупочным ценам и внутренней статистике агентов.

### 3. Каталог товаров

Создать каталог с категориями.

Каждый товар должен содержать:

- ID товара.
- SKU (артикул).
- Название.
- Описание.
- Категорию.
- Основную фотографию.
- Дополнительные фотографии.
- Закупочную цену.
- Рекомендованную розничную цену.
- Минимальную допустимую цену продажи.
- Складской остаток.
- Статус товара (активен / скрыт / закончился).
- Дату добавления.

Карточка товара должна отображать:
- Фотографию.
- Название.
- Краткое описание.
- Цену для агента.
- Рекомендованную цену продажи.
- Доступное количество.

### 4. Система наценок

Агент должен иметь возможность устанавливать собственную наценку на товары.

Пример:

Закупочная цена: 50 000 сум.

Рекомендованная цена: 70 000 сум.

Цена продажи агентом: 75 000 сум.

Прибыль агента: 25 000 сум.

Система должна автоматически рассчитывать прибыль агента.

Администратор может:
- Установить минимальную цену продажи.
- Установить рекомендованную цену.
- Ограничить максимальную наценку.
- Запретить изменение цены агентом для отдельных товаров.

### 5. Система заказов

Заказ должен содержать:

- Уникальный номер заказа.
- Дату создания.
- ID агента.
- ID покупателя.
- Список товаров.
- Количество каждого товара.
- Закупочную стоимость.
- Цену продажи.
- Прибыль агента.
- Общую сумму заказа.
- Имя покупателя.
- Телефон покупателя.
- Адрес доставки.
- Комментарий к заказу.
- Статус заказа.

Статусы заказа:

1. Новый.
2. Подтверждён.
3. Собирается.
4. Передан в доставку.
5. Доставлен.
6. Отменён.

При оформлении заказа система должна:
- Проверить наличие товаров.
- Проверить корректность цены.
- Сохранить заказ в базе данных.
- Зарезервировать товары на складе.
- Уведомить администратора через Telegram.
- Отобразить агенту номер заказа.

Списание товаров должно происходить согласно утверждённой логике складского учёта, исключая двойное списание.

### 6. Telegram-бот

Интегрировать Telegram-бота для уведомлений администратора.

При новом заказе бот отправляет сообщение:

Агент: Джахонгир  
Телефон агента: +998 XX XXX XX XX

Покупатель: Али  
Телефон: +998 XX XXX XX XX

Адрес доставки: Ташкент

Товары:
- Миска для кошек — 2 шт.
- Игрушка для собак — 1 шт.

Закупочная стоимость: 120 000 сум  
Сумма продажи: 180 000 сум  
Прибыль агента: 60 000 сум

Статус: Новый

Telegram-бот должен поддерживать:
- Уведомление о новом заказе.
- Уведомление об отмене заказа.
- Уведомление об изменении статуса заказа.

### 7. Регистрация и авторизация

Регистрация осуществляется по номеру телефона.

Требования:
- Номер телефона должен быть уникальным.
- Формат номера: +998XXXXXXXXX.
- Авторизация по номеру телефона и паролю.
- Возможность восстановления пароля.
- Возможность подтверждения номера через SMS.
- Защита от повторной регистрации.
- Безопасное хранение паролей.

Роль пользователя назначается администратором либо системой по предусмотренной бизнес-логике.

### 8. Административная панель

Создать отдельную админ-панель.

Разделы:

1. Dashboard.
2. Товары.
3. Категории.
4. Заказы.
5. Пользователи.
6. Агенты.
7. Статистика.
8. Настройки.

Dashboard должен отображать:
- Общее количество товаров.
- Количество заказов.
- Количество активных агентов.
- Общую сумму продаж.
- Количество новых заказов.
- Товары с низким остатком.
- Топ-10 продаваемых товаров.
- Топ-10 агентов по продажам.

### 9. Личный кабинет агента

Создать отдельную панель агента.

Разделы:
- Главная.
- Каталог.
- Мои заказы.
- Мои продажи.
- Моя прибыль.
- Персональные ссылки.
- Профиль.

Dashboard агента отображает:
- Количество заказов.
- Общую сумму продаж.
- Прибыль.
- Количество доставленных заказов.
- Количество отменённых заказов.

### 10. Дизайн

Стиль: минимализм, современный e-commerce.

Требования:
- Светлая тема.
- Белый фон.
- Чёрный и серый текст.
- Акцентный цвет — зелёный.
- Чистая типографика.
- Карточки товаров с аккуратными тенями.
- Минимум визуального шума.
- Адаптивность для мобильных устройств.
- Удобная навигация.
- Быстрая загрузка страниц.

Интерфейс должен быть похож на современный SaaS-продукт.

### 11. Технологический стек

Рекомендуемый стек:

Frontend:
- HTML5.
- CSS3.
- JavaScript.
- Tailwind CSS.

Backend:
- PHP 8.2+.
- REST API.

База данных:
- MySQL 8.

Дополнительно:
- Telegram Bot API.
- Session-based authentication или JWT.
- Защита от SQL Injection.
- Защита от XSS.
- Хеширование паролей.
- Валидация всех форм.

### 12. Архитектура

Система должна иметь разделение на:

- Frontend.
- Backend API.
- Базу данных.
- Административную панель.
- Кабинет агента.
- Telegram-интеграцию.

Все бизнес-операции должны выполняться через backend.

Frontend не должен иметь прямого доступа к базе данных.

### 13. Безопасность

Обязательно:
- Проверка ролей на сервере.
- Защита админ-панели.
- Безопасное хранение паролей.
- Защита от CSRF.
- Защита от SQL Injection.
- Проверка наличия товара при оформлении заказа.
- Запрет изменения закупочной цены агентом.
- Логирование административных действий.
- Защита от повторного оформления одного заказа.

### 14. MVP — первая версия

В первую версию должны входить:

1. Регистрация и авторизация.
2. Ролевая система.
3. Каталог товаров.
4. Админ-панель.
5. Управление товарами.
6. Управление складом.
7. Оформление заказов.
8. Кабинет агента.
9. Telegram-уведомления.
10. История заказов.
11. Адаптивный дизайн.

Не включать в первую версию:
- Онлайн-оплату.
- Автоматические выплаты агентам.
- SMS-интеграцию, если она требует отдельного бюджета.
- Сложную CRM.
- Многоуровневую реферальную систему.

### 15. Результат разработки

Разработчик должен предоставить:

- Полностью работающий сайт.
- Исходный код.
- SQL-файл базы данных.
- Инструкцию по установке.
- Инструкцию по созданию администратора.
- Настройку Telegram-бота.
- Готовую систему управления товарами и заказами.
- Рабочую регистрацию и авторизацию.
- Возможность дальнейшего масштабирования платформы.
